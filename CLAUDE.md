# Staff the Game

## Demo data — do not reseed without explicit permission

Never run `scripts/cleanupDemoData.mjs` or `scripts/seedDemoData.mjs` unless the
user explicitly asks for a reseed in that conversation. Don't run them
proactively after seed-script edits, as part of a "deploy when done," or to
verify a seed-script change — editing the script and confirming it parses/runs
cleanly (e.g. `node -c scripts/seedDemoData.mjs`) is enough without touching
live data.

Why: every reseed deletes all demo accounts and recreates them with new
`RUN_TAG`-suffixed emails (see `scripts/seedDemoData.mjs`), so all demo logins
change. The user also has to manually re-set `isAdmin: true` on the employer
account in the Firebase console afterward, since the seed script runs as a
regular signed-in user and Firestore rules correctly block self-granting
`isAdmin` (see `firestore.rules`) — there's no admin-SDK path wired up for it.

Current demo credentials live in `demo-credentials.local` (gitignored,
regenerated by `seedDemoData.mjs` each time it runs) — read that file instead
of reseeding to get up-to-date logins.
